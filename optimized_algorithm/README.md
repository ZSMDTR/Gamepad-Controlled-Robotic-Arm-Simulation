# 末端位姿控制算法（独立核心）

本目录是项目实际使用的算法核心，不依赖 MuJoCo，只依赖 Python 与 NumPy。`pose_control.py` 接收机械臂的测量状态和雅可比矩阵，输出关节位置参考；`example.py` 是独立的最小调用示例。MuJoCo 的模型解析、执行器、页面和手柄输入在本目录之外。旧的 `arm_teleop.pose_control` 路径保留兼容导入，不维护第二份算法副本。

## 选择的方向

选择 **约束感知的阻尼差分逆运动学**（页面“约束 DLS”，内部名 `constrained_dls`）作为本项目下一步重点研究方向。它将手柄意图转换成末端速度，再结合当前模型的雅可比与各关节参考范围求解；当某关节受到限制时，其余关节可以参与补偿。原 DLS 仍是默认选项，便于对照。本方法在不同模型和轨迹上的实测有利有弊，尚不能称为全场景最优。

## 怎样工作

1. 手柄或键盘给出位置、转动和使能意图；目标以固定周期更新，并限制目标超前实际末端的距离。
2. 根据位置误差及旋转矩阵误差构造六维目标速度；对转动部分乘一个长度尺度，得到 `v`，对对应雅可比得到 `J`。该尺度决定平移与姿态的相对权重，并非物理常数。
3. 在每个关节的可行速度区间内，求解一个有界阻尼最小二乘问题：

   `min ||J·qdot − v||² + λ² ||qdot − qdot_posture||²`

   区间综合参考速度、每周期参考加速度、接近关节限位的制动包络以及关节参考领先限制。活动集方法根据触及边界的关节重新求解；`λ` 用于抑制奇异方向上的过大解，姿态项表达回到初始姿态的偏好。它并不保证严格的位置优先或任意位姿可达。
4. 输出位置参考 `q_ref` 交给下游位置执行器；MuJoCo 再根据执行器和动力学推进，下一周期读回实际状态。松开使能后控制器减速并重新锚定目标；输入超时停止输入的逻辑由外层服务实现。

## 创新切入点与边界

- **本项目的工程组合**：将标准手柄六维意图、模型配置映射、参考约束感知求解、状态提示和仿真回放整合，适合比较不同机械臂。约束差分 IK、活动集方法本身已有研究，不能据此声称学术首创。
- **约束冲突可解释**：当参考约束因测量突变等原因无法同时满足，控制器标记冲突并尝试保持参考连续；可能需要暂时放宽参考领先、制动或加速度约束。求解达到迭代上限也会标记。输出仅为仿真参考，不是实体机械臂安全保障。
- **跨型号公平对照**：`scripts/compare_pose_methods.py` 在相同输入、模型初始状态和限值下比较旧 DLS 与新模式。建议继续扩展方向误差、奇异位形、停止距离及真实手柄延迟；这些不是当前已完成的全面验证。

[SDLS 原论文](https://math.ucsd.edu/~sbuss/ResearchWeb/ikmethods/SdlsPaper.pdf)、[Mink](https://github.com/kevinzakka/mink/)、[SNS 论文](https://www.diag.uniroma1.it/~labrob/pub/papers/ICRA12_RedundancySNS.pdf) 和 [Ruckig](https://github.com/pantor/ruckig) 是相关研究或开源参考。更详细的区别与限制见 `../docs/algorithm-references.md`。

## 独立调用

从项目根目录运行：

```powershell
.venv\Scripts\python.exe -m optimized_algorithm.example
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe scripts/compare_pose_methods.py --output optimized_algorithm/comparison-results.json
```

适配其他模型时，调用方负责提供与关节顺序一致的下界、上界、速度和加速度参考限值，以及测量关节位置、TCP 位置、旋转矩阵和世界坐标系下 6×n 几何雅可比。必须自行核对单位、坐标系、执行器及模型动态；不同自由度的机械臂不保证同样的运动能力。控制周期仅为软实时；碰撞、抓取、真实硬件及完整实机安全尚未验证。

## 一次本机对照结果

2026-11-06，在这台 Windows 电脑上离线回放：每组相同模型初态和 8 秒输入，800 个 10 ms 控制周期。下表的误差针对两种算法共同的、未截断输入目标；该目标不一定可达。25% 是人为收紧的参考速度与加速度限值。时间是控制器单步耗时，不含浏览器、网络、手柄和实际执行器。

| 模型与参考限值 | 方法 | 位置 RMS (mm) | 朝向 RMS (rad) | 控制器 p99 (ms) |
| --- | --- | ---: | ---: | ---: |
| UR5e 默认 | DLS | 15.02 | 0.0629 | 0.458 |
| UR5e 默认 | 约束 DLS | 15.95 | 0.0719 | 1.228 |
| Panda 默认 | DLS | 72.05 | 0.0564 | 0.444 |
| Panda 默认 | 约束 DLS | 57.95 | 0.0821 | 1.090 |
| UR5e 25% | DLS | 45.21 | 0.1582 | 0.465 |
| UR5e 25% | 约束 DLS | 52.33 | 0.1700 | 0.928 |
| Panda 25% | DLS | 95.16 | 0.1638 | 0.509 |
| Panda 25% | 约束 DLS | 79.52 | 0.1504 | 1.134 |

这些结果显示约束 DLS 在本次 Panda 轨迹上的位置误差较低，但 UR5e 和部分姿态误差更高，耗时也更长；不能推出它在所有轨迹或所有型号上更好。离线计时受系统负载影响，不能推断闭环实时率。完整结果见 `comparison-results.json`，可用上方命令复现；软件会覆盖该结果文件。
