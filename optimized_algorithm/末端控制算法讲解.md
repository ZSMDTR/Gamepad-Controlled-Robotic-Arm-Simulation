# 末端控制算法讲解

## 这套算法解决什么问题？

想象夹爪前端有一个小点，叫 TCP（工具中心点）。使用者只需表达“让这个点往前、往后、往左、往右、往上、往下”，或者“绕某个方向转动”，不必分别计算六个关节需要转多少。算法根据机械臂当前状态，把这些意图换算成各关节的位置参考；仿真中的电机再尝试跟随这些参考。

本项目用于 B601 场景时，参照固定的**世界坐标系**：+X 是从底座朝桌面，+Y 是机械臂自身左侧，+Z 是向上。三个负方向分别相反。观察者旋转相机时，画面上的左右会改变，但这些坐标方向不会跟随相机或夹爪转向。其他模型需核对自己的世界坐标和 TCP 定义。

旋转输入表示绕世界坐标轴转动夹爪姿态。它控制的是 TCP 的位置和朝向，并不直接控制被夹物体的中心：如果物体中心与 TCP 有偏移，夹爪转动时，物体中心也会绕 TCP 移动。夹爪开合是另一条命令，不在六维末端逆运动学求解中。

## 文件与数据流

这里的 [pose_control.py](pose_control.py) 就是程序实际调用的单一算法实现，只依赖 NumPy；[example.py](example.py) 展示如何调用。`arm_teleop/pose_control.py` 是兼容导入，不是另一套算法。具体数据流为：

```text
手柄/键盘 → 世界坐标下的平移、旋转意图
          → 更新 TCP 目标位置和目标朝向
MuJoCo → 当前关节状态、TCP 位姿、6×n 雅可比
          → 末端位姿误差 → 差分逆运动学 → 关节位置参考
          → MuJoCo 执行器与物理仿真 → 下一周期重新测量
```

MuJoCo 适配器在 `arm_teleop/mujoco_backend.py`，每次仿真控制周期在 `arm_teleop/server.py`。它们负责读取模型和执行参考；核心算法既不读取 MuJoCo 模型，也不直接控制实体机械臂。`scripts/native_input.py` 负责把原生窗口的操作转换为输入，具体按键以当前使用说明为准。

## 每个周期发生什么？

1. **设定目标。** 第一次使能时，以当前测得 TCP 作为目标起点。平移输入乘以设定速度和时间步长，累加到目标位置；转动输入则更新目标旋转矩阵。输入向量过长时按整体长度缩放，避免对角线命令天然比单轴更快。
2. **计算误差。** 位置误差为目标位置减去当前 TCP 位置。姿态误差是从当前姿态旋转到目标姿态的旋转向量，单位是弧度。目标领先当前状态的距离和角度会被限制，避免不可达目标无限积累。
3. **求解关节速度。** 模型提供雅可比矩阵 `J`，它描述在当前姿态附近，关节的微小运动如何影响 TCP 的平移和旋转。算法根据末端误差生成希望达到的线速度和角速度，再通过差分逆运动学计算关节速度参考。
4. **限制并输出。** 算法对关节速度、加速度和位置参考应用限制，得到 `q_ref`。下游位置执行器追踪 `q_ref`，仿真推进后重新测量。松开使能时停止累积目标并重新锚定；原生窗口还会清除已积累的关节参考领先量。

以上是离散闭环控制，并不是一次算完所有轨迹。当前仿真以 **10 毫秒**为名义控制周期；实际时序受操作系统调度、计算及渲染负载影响，并非硬实时。

## 核心数学：从末端运动到关节运动

设 `q̇` 为关节速度，`v` 为希望的 TCP 线速度和角速度，局部近似满足 `J q̇ ≈ v`。因为机械臂姿态可能接近奇异、无法实现某个方向，直接求逆可能产生过大的关节速度。阻尼最小二乘（DLS）改为求：

```text
最小化   ||J q̇ − v||² + λ² ||q̇||²
```

其中 `λ` 是阻尼参数：适当阻尼可抑制过大的速度，但也会带来跟踪误差。本实现会先把角速度及对应雅可比乘以同一个长度尺度，以调整姿态与平移的相对权重。DLS 使用奇异值分解求解；之后还可加入回到初始姿态的偏好，并执行关节参考限制。

代码还包含位置优先、实验性 SDLS 和约束 DLS 等模式。位置优先先解平移，再尽量在不影响平移的一阶零空间内求转动；后续速度、加速度等限制及仿真动力学仍可能改变结果。约束 DLS 把部分关节参考界限纳入求解，也不代表末端每个方向都一定可达。当前选用的模式以运行配置为准，不应把所有模式当作同时生效。

这次原生 MuJoCo 窗口采用**约束 DLS**：求解时考虑关节参考的速度、加速度、接近限位的制动和参考领先范围；当各约束在某周期相互冲突时，代码会标记并放宽部分参考约束，以保持连续性。原生控制的参数入口是 [native_control.py](native_control.py)：最大平移参考速度为 0.05 米/秒，最大旋转参考速度为 0.3 弧度/秒，目标位置最多领先当前 TCP 0.02 米，姿态目标领先上限为 0.08 弧度，姿态长度尺度为 0.12，姿态回中偏好设为零。它们是控制目标或参考的设置，不保证实际机械臂的运动严格达到这些数值。在原生窗口中，旋转输入回中、反向或改轴的瞬间，外层 `Simulation.tick` 会将姿态目标重新对齐当前测量姿态一次，避免旧角度积压，同时保留关节参考的连续性；单独调用 `PoseController` 时需要调用方自行处理这一输入事件。原网页默认仍使用 DLS，页面上可选择其他模式。

**坐标方向明确不等于物理轨迹严格无误差。** 奇异姿态、关节限位、碰撞、受力、速度和加速度限制、离散时间以及姿态与位置任务相互竞争，都可能造成侧向漂移或目标无法到达。控制器不做通用避障，也不保证物体抓取成功。接近这些情况时，应降低速度、改变姿态或重新规划路径；不能把仿真结果直接视为实机安全保证。

## 单独运行和接入其他机械臂

在项目根目录执行：

```powershell
# Windows
.venv\Scripts\python.exe -m optimized_algorithm.example
```

```bash
# Linux
.venv/bin/python -m optimized_algorithm.example
```

示例中的单位矩阵只是便于理解接口的虚构雅可比，运行它不会连接或移动机械臂，也不验证某一型号。要接入真实模型，调用者至少需要：

- 按从底座到 TCP 的一致顺序提供关节位置、关节速度、上下限以及参考速度和加速度限值。旋转关节用弧度，平移关节用米；对应速度和加速度采用每秒及每秒平方的单位。
- 每周期提供世界坐标下 TCP 的位置（米）、姿态（3×3 旋转矩阵）和几何雅可比（形状 `6×n`，前三行线速度，后三行角速度），列顺序必须与关节顺序一致。
- 将世界坐标下 `[-1, 1]` 的平移和旋转意图、使能状态和秒为单位的周期传入 `PoseController.step`，再将返回的 `q_ref` 交给对应关节的位置执行器。当前接口接受 `qvel` 并校验其形状，但核心求解未把它用作反馈阻尼项。
- 实现适合目标系统的输入超时、使能、关节保护、碰撞处理和执行器控制。仅复制算法文件并不能自动完成这些适配，也不意味着任意自由度、任意硬件都可实现相同运动。

程序参数（如 `cartesian_speed`、`angular_speed`、`damping`、`length_scale`、目标领先上限）在 `PoseController` 的 `spec` 中设置；限值应依据实际模型和执行器确定。修改后要在对应模型和任务范围重新验证方向、精度、限位及停止行为。
